# Traffic

A convolutional neural network (CNN), built with TensorFlow/Keras, that classifies images of German traffic signs into 43 categories.

## Dataset

This project requires the [GTSRB (German Traffic Sign Recognition Benchmark)](https://benchmark.ini.rub.de/) dataset, which is **not included in this repository** (it is roughly 238MB / 26,640 images). Download it separately, e.g. from the CS50AI course site (`https://cdn.cs50.net/ai/2023/x/projects/5/traffic.zip` contains a `gtsrb` folder), and place it alongside `traffic.py` as a `gtsrb/` directory containing one numbered subfolder per category (`gtsrb/0/`, `gtsrb/1/`, ... `gtsrb/42/`), each holding that category's training images. Then run:

```
python traffic.py gtsrb [model.h5]
```

## Model analysis / notes

through experimenting, i realised that having more conv and pooling layers were benficial with the limited amount of epochs given. this limited amount of epochs given really, promoted the need to drastically improve the architecture. Another evident beenfit was not only having more hidden layers, but the droput layers underneath them were essential as well. having an increasing amount of filters for each conv layer was also beneficial, and upon furhter research showed me the purpose by getting global features or more micro features of an image. Conversely, i did a decreasing nubmer of neurons for each hidden layer, which seems beneficial to my assumption, since the output layer expects 10, and that we start at 64, it was wise to corner the calculations down close to the expected value for the output in my opinion although this is still unsure to me. ANother really big factor was, experimenting with activation functions for each part of the architecture, from ym previous testing usign relu in general and softmax for the output layer was always best practice, but then using a sigmoid function at the start of the conv layers, had a big big impact in improving the model, upon some brief research is seems this is because relu may cause dying neurons due to the way it calculates outputs of negative results, causing the neurons to output zero, where as the signmoid functions consider negative calculations as well. although a relu is better at the third layer as it has more decisive and maximising results, when needed, the middle layer of the conv and pooling phase, used a leaky_relu, which i heard was inbetween relu and sigmoid, as sigmoid may cause vanishing gradients and relu avoid that. Changing the second layer from relu to leaky_relu seems to also have slightly improved the model. it makes me think about the effects of activation functions and different ones accross multiple layer, the conv and pooling layers or backbones of the computer vision task having a bigger impact and being more dynamic according to the dataset at hand. and wodnering how to dynamically yet assuringly fix this issue everytime. Further attemps with experimenting with using sigmoid for multiple conv layers deems to have a degrading effect, yet having a vairety of activation function types seems to improve it as using tanh in the middle layer, does seem to ahve a similar effect as using leky_relu at 49% accuracy but slightly worse as leaky_relu version provided a 50~53% accuracy model. THis gives me a big indication for futre model engineering especially for computer vision that having multiple conv layers with different activation functions in each will ahve a big effect on the models accuracy.
